# Fair-play mystery design

A mystery is only "solvable" if the user could, in principle, have reached
the correct answer from what's given to them *before* the reveal. Check
the case against these rules while building it:

**Every clue that matters must be shown, not just known.** If the solution
depends on a fact, that fact (or evidence pointing to it) must appear in
the public premise, the timeline, or the evidence the user is told about
during investigation — never introduced for the first time in the reveal.
A twist that relies on information the user was never given isn't a twist,
it's an unfair surprise.

**Red herrings must be plausible but ultimately explicable.** A false lead
should look genuinely suspicious on its own terms (motive, opportunity, or
behavior that reads as guilty) but have an innocent explanation that holds
up once examined — not just "turns out it wasn't them" with no reason why
the suspicious-looking thing happened.

**Exactly one suspect must be logically supportable as the culprit** given
the full set of shown clues — not the most dramatically interesting choice,
the one the evidence actually, uniquely points to. If two suspects are
equally supportable by the shown evidence, the case is broken, not
ambiguous-in-a-good-way.

**The method and motive must be internally consistent** with everything
else established about the case (timeline, character established
personalities/relationships, physical constraints of the scene) — a
solution that requires contradicting an earlier established fact is a
validator failure, not an acceptable twist.

Apply this as a checklist during the validator step specifically: for each
rule, confirm it holds against what's actually been written into the case
record, don't just assume it does because the story feels complete.
